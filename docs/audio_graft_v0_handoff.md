# Audio Ear Graft v0 — Implementation Handoff

**Mission in one line:** give `Qwen3.5-4B` (a text+vision LLM with no audio path) working ears by stacking the frozen `Qwen3-Omni-30B` audio tower on top of it, training exactly **one linear projection layer** (~5.2M params) on (audio, text) pairs generated by the Qwen3-Omni-30B teacher.

Read this whole doc before writing code. Everything in §2 was **verified on this machine on 2026-10-20** — trust it, but re-verify cheaply if something looks off.

---

## 1. Goal / Non-goals

### v0 IS
- A stage-0 **ear-alignment** pass: after it, the 4B must treat audio embeddings as meaningful signal (audio-conditioned, coherent, discriminative within the 0–8 kHz band).
- Architecture: frozen omni audio tower + frozen Qwen3.5-4B + one trainable `Linear(2048 → 2560)`.
- 16 kHz **mono** front-end, stock (the omni tower's native input).
- Data: a few hundred to a few thousand (audio, text) pairs, text generated by the Qwen3-Omni-30B (or 7B fallback) as offline teacher over local audio.
- Thinking mode **off** during training (the 4B is a hybrid thinking model — thinking is a generation-time template toggle, not a separate checkpoint; see §2.3).

### v0 is NOT (defer to v1, see §10)
- Not the final model — downstream agentic training (the actual DawDreamer/synth work) builds on top of this.
- Not wide-band (44.1 kHz / 8–22 kHz) and not stereo. Both are small follow-ups (documented in §10) but out of scope here.
- Not bulletproof frequency identification. The pass bar is "wired and roughly calibrated" (§7).
- No 4B LoRA in v0 (pure projector). Only if projector-only loss doesn't drop do we add a tiny LoRA (v0.5).
- No new tokenizer tokens (audio tokens already exist in the 4B vocab — §2.3).

### 2.2 The audio tower (source: Qwen3-Omni-30B)

- Class: `transformers.models.qwen3_omni_moe.modeling_qwen3_omni_moe.Qwen3OmniMoeAudioEncoder` (defined at line 625 of that file). **Copy it** into the project (with its config class `Qwen3OmniMoeAudioEncoderConfig`, `Qwen3OmniMoeAudioEncoderLayer`, `SinusoidsPositionEmbedding`, and the module-level `_get_feat_extract_output_lengths`) — do NOT subclass installed transformers in place.
- **648M params** (verified by summing safetensors shapes). In the omni checkpoint every weight key is prefixed `thinker.audio_tower.*` (525 tensors).
- Config values (from the 30B `config.json` → `thinker_config.audio_config`):
  - `d_model: 1280`, `encoder_layers: 32`, `encoder_attention_heads: 20`, `encoder_ffn_dim: 5120`
  - `num_mel_bins: 128`, `downsample_hidden_size: 480`, `output_dim: 2048`
  - `n_window: 50`, `n_window_infer: 800`, `conv_chunksize: 500`, `max_source_positions: 1500`
- Forward signature (line 698): `forward(input_features, feature_lens=None, aftercnn_lens=None, **kwargs)`
  - `input_features`: `(B, T_mel, 128)` mel spectrogram (WhisperFeatureExtractor output)
  - `feature_lens`: `(B,)` mel-frame counts (sum of feature_attention_mask)
  - returns hidden states `(B, T_out, 2048)` where `T_out = _get_feat_extract_output_lengths(feature_lens)`
  - internal chunking (n_window=50) handles clips longer than one window; convs run in `conv_chunksize=500` batches to avoid OOM.
- Conv stack: `conv2d1 = Conv2d(1, 480, 3, stride 2)` ← **`in_channels=1` is where mono is hardcoded** (the v1 stereo hook), then `conv2d2`, `conv2d3` (both `480→480, 3, stride 2`), then `conv_out = Linear(480*16, 1280)`, 32 transformer layers, `ln_post`, `proj1 = Linear(1280,1280)` + gelu, `proj2 = Linear(1280, 2048, bias=False)`. We freeze **all** of it including `proj2` (its 2048-dim output is what our new projector consumes).
- Feature extractor (omni checkpoint `preprocessor_config.json`): `WhisperFeatureExtractor`, `feature_size: 128`, `n_fft: 400`, `hop_length: 160`, `sampling_rate: 16000`, `n_samples: 4800000` (300 s max), mono **required** (it raises on stereo).
- Token-count formula (copy verbatim):
  ```python
  def _get_feat_extract_output_lengths(input_lengths):
      input_lengths_leave = input_lengths % 100
      feat_lengths = (input_lengths_leave - 1) // 2 + 1
      output_lengths = ((feat_lengths - 1) // 2 + 1 - 1) // 2 + 1 + (input_lengths // 100) * 13
      return output_lengths
  ```
- Token semantics in the omni chat template: `audio_start (151669)` `audio (151675)` × N `audio_end (151670)`. In the **4B vocab** the same *characters* are: **start = 248070**, **placeholder = 248076**, **end = 248071**.

## 3. Architecture (v0)

```
wav (44.1k stereo)
  → downmix mono → resample 16 kHz                [preprocessor, no params]
  → WhisperFeatureExtractor → mel (T, 128)        [frozen FE config]
  → Qwen3OmniMoeAudioEncoder (648M)               [FROZEN; from omni ckpt, keys thinker.audio_tower.*]
      output (T_out, 2048)
  → audio_projector = nn.Linear(2048, 2560)       [THE ONLY TRAINABLE MODULE — 5,245,440 params w/ bias]
      output (T_out, 2560)
  → inputs_embeds = inputs_embeds.masked_scatter(audio_mask, audio_embeds)
      where audio_mask = (input_ids == 248076)    [Qwen3.5-4B, FROZEN]
  → LM loss on target-text tokens only
```

- Sequence format per sample:
  ```
  [user turn]  Describe this sound.  <audio_start> <audio>×N <audio_end>
  [assistant]  <caption text>
  ```
  (`N = _get_feat_extract_output_lengths(T_mel)`; exact template wording in §5.3.)
- Positions: audio tokens get sequential positions (M-RoPE mm type 0 = text).
- Loss masking: everything except the assistant caption tokens (ignore_index on prompt/audio/specials).

**Freeze checklist** (assert in code, fail loud):
- `audio_tower.*` all `requires_grad == False`
- 4B text + vision modules all `requires_grad == False`
- trainable params == projector exactly (report the count; expect 5,245,440 if bias kept — match omni's `proj2` which is `bias=False`; **decision: keep bias=False to mirror omni → 5,242,880 params; log whichever you choose**)

### 5.2 `modeling_qwen3_5_audio.py` — patches to the copied 4B file

1. **Config**: add fields to the model config (in `config_audio.py`): `audio_token_id: 248076`, `audio_start_token_id: 248070`, `audio_end_token_id: 248071`, `audio_config: <omni audio_config dict from §2.2>`.
2. **`__init__` of the multimodal model class**: after the vision tower is built:
   ```python
   self.audio_tower = Qwen3OmniMoeAudioEncoder(config.audio_config)
   self.audio_projector = nn.Linear(2048, config.text_config.hidden_size, bias=False)
   ```
   (2048 = `config.audio_config.output_dim`; 2560 = `config.text_config.hidden_size`.)
3. **New method** `get_audio_features(input_features, feature_attention_mask)` mirroring `get_image_features` (line 1511):
   ```python
   feature_lens = feature_attention_mask.sum(-1)
   embeds = self.audio_tower(input_features, feature_lens=feature_lens)   # (B, T_out, 2048)
   return self.audio_projector(embeds)                                    # (B, T_out, 2560)
   ```
   Flatten per-sample before `masked_scatter` (the mask is per-token, features must be one flat `(Σ T_out, 2560)` tensor — same treatment vision does via split/concat).
4. **Extend `get_placeholder_mask`** (line 1534): add `audio_features=None` param; build `special_audio_mask = input_ids == self.config.audio_token_id` (+ embeds-based fallback like vision does when `input_ids is None`); same `numel()` check; return it as a third mask.
5. **Forward** (inner model, ~line 1653): after the image/video blocks:
   ```python
   if input_features is not None:
       audio_embeds = self.get_audio_features(input_features, feature_attention_mask)
       _, _, audio_mask = self.get_placeholder_mask(input_ids, inputs_embeds=inputs_embeds, audio_features=audio_embeds)
       inputs_embeds = inputs_embeds.masked_scatter(audio_mask, audio_embeds)
   ```
   Thread `input_features` / `feature_attention_mask` through the `ForConditionalGeneration.forward` signature and the inner model's forward (mirror how `pixel_values`/`image_grid_thw` are threaded).
6. **Positions**: do NOT add audio to the M-RoPE mm-type logic. Verify `get_rope_index`/`compute_3d_position_ids` treats an all-text mm type vector as sequential (it must, since text-only inputs already work). If the processor forces `mm_token_type_ids` construction from grid tensors, make it emit all-zeros when only audio is present. **This is the spot most likely to bite — write a unit test: audio-only sample → position_ids strictly increasing.**
7. **Weight loading** (in `config_audio.py` or a small loader):
   - Load 4B weights from the 4B checkpoint as usual.
   - Load tower weights from the omni checkpoint with key remap: strip the `thinker.audio_tower.` prefix → `audio_tower.*` (525 tensors; assert all matched, assert none missing/unexpected).
   - `audio_projector`: fresh init (default `kaiming_uniform` is fine).
   - For inference convenience also support dumping a **merged single checkpoint** (both weight sets under the new naming).
8. **Smoke asserts** (run at import time of `train_projector.py`):
   - trainable params == projector only, exact count logged
   - a 1-second silent clip end-to-end: shapes line up, loss finite, `masked_scatter` count check passes

### 5.3 `preprocessor.py`

- `WhisperFeatureExtractor` built from the omni checkpoint's `preprocessor_config.json` values (§2.2) — or instantiate `from_pretrained` on the omni snapshot and reuse its `feature_extractor`.

- Text (single template for v0, keep it boring):
  ```
  user:      <|im_start|>user\nDescribe this sound.<|im_end|>\n<|im_start|>assistant\n
  audio:     injected as  <start> <audio>×N <end>  at the start of the user turn (before "Describe")
  ```

### 5.4 Clip length policy

- v0: cap at **30 s** (100 mel frames/s × 30 = 3000 frames; tower chunks in 100-frame windows, positional embedding covers 1500 → fine). Most local clips are 10 s anyway.
- 16 kHz × 30 s = 480k samples ≤ FE `n_samples` 4.8M — no FE-level cap hit.

## 7. Evaluation — the ear test

Run **before training** (to prove the 4B has no ear), **after stage 0**, and keep as a regression suite.

1. **Discrimination probes** (~40 pairs, all in-band ≤8 kHz for v0): A/B renders with one known difference each — bright vs dark filter cutoff, fast vs slow LFO wobble, pluck vs sustain envelope, sine vs saw timbre, clean vs distorted, high vs low pitch class. Prompt: "Which one is the {property}?" / "Describe the difference." Score: accuracy. **Pass bar v0: ≥70% on the 4 clearest categories, and ≥10 pts above the shuffled-label baseline.** (The 30B-teacher's own accuracy on the same probes is the sanity ceiling — record it too.)
   - Reuse DawDreamer renders (see `docs/dawdreamer-state-format.md`) or the existing `data/` wavs; a small render script with 8–12 fixed patch pairs is ~50 lines.
2. **Caption coherence**: 100 held-out local renders → grafted-model captions. Check: non-degenerate (no repeated tokens, no special-token leakage), audio-conditional (below), and plausible (auto-judge: 30B-omni-as-judge pairwise preference vs the *teacher's own* caption of the same clip — the grafted 4B caption should not lose >50% of pairings in v0).
3. **Negative control (required)**: same forward pass with `input_features` zeroed (keep the tokens). Output must degrade measurably (higher loss on the true caption, lower discrimination accuracy). Proves conditioning comes from the audio signal, not the placeholder tokens or position tricks.
4. **Unit tests** (in CI of the script): position-ids strictly increasing for audio-only input; `masked_scatter` numel check trips on a deliberately wrong N; freeze-assert passes.

## 8. Training recipe

- **Where**: container `qpid-train:26.09` (has CUDA 13.4 + nvcc + torch; if its transformers lacks `qwen3_5`/`qwen3_omni_moe` model files, `pip install transformers==<venv version>` inside the container — allowed, it's container-local). Run pattern per `~/ml/docker/qpid-train/` + `~/q-pid/configs/docker_train.sh`: `docker run --device nvidia.com/gpu=all --ipc=host --user $(id -u):$(id -g) -e PYTHONNOUSERSITE=1 -v /home/nate:/home/nate`.
  - Single GPU is enough (≈11 GB model + activations); request one device to be polite.
- **Optimizer**: AdamW, **lr 2e-3** (projector-only training tolerates high lr; sweep {1e-3, 2e-3, 5e-3} on 200 pairs first), weight_decay 0, no scheduler tricks (linear decay over the run is fine).
- **Batching**: micro-batch 2–4 × grad-accum to effective 32–64; bf16; grad-clip 1.0. Clips ≤30 s.
- **Steps**: 1–2k pairs × 3–5 epochs → thousands of steps; expect **under a few hours** on one 3090.
- **HF Trainer or plain loop**: either; the repo has ms-swift 4.0.2 + Megatron for the big recipes but this toy-sized task doesn't need them — a plain HF `Trainer` (or a 100-line loop) is less machinery and easier to debug.
- **Checkpointing**: save projector weights (a few MB) every 500 steps + best-by-val-loss; save one merged full checkpoint for inference/eval.
- **Val split**: hold out 10% of pairs by clip (not by caption) for val loss.

## 9. Context: why this shape (for the implementer's judgment calls)

- The omni audio tower (648M) is the "expensive ear" — 32-layer Whisper-style encoder co-trained inside Qwen3-Omni. We keep it frozen and borrowed.
- Qwen3.5-4B was chosen because it is (a) small/1-card, (b) natively agentic (tools + thinking in its template — no format fights, unlike Qwen2.5-Omni whose released template drops `tools` entirely), and (c) already ships the audio placeholder tokens in its vocab, built as a vision-conditional architecture — i.e., the graft is a *completing* move, not a hack.
- Teacher targets come from the same family (Qwen3-Omni) so the text distribution is on-policy for what we'll ask downstream; captions reflect the teacher's 16 kHz-mono hearing — that's fine and expected for v0 (the wide-band/stereo axes come from manufactured data in v1).
- v0 deliberately does NOT retrain the tower's front-end convs (that's the ~15–20M wide-band/stereo upgrade in v1). If ear-test discrimination is weak *in-band* (<8 kHz), suspect the projector lr/data before touching the tower.

## 10. Explicitly deferred (v1 checklist — do NOT build in v0)

1. **Wide-band front-end**: 128-bin mel computed from 44.1 kHz over 0–22 kHz (same geometry, ~2.75× wider bins) → retrain `conv2d1..3 + conv_out` (~15–20M), optionally LoRA the first ~4 encoder layers.
2. **Stereo**: `conv2d1` `in_channels 1→2` (4,320 params) — or double-encode L/R through the frozen mono tower and give the projector a 2560-dim input.
3. **Token rate**: extra stride-2 conv (4K params) → ~17 audio tokens/s instead of ~34 at 44.1k.
4. **Temporal positions**: omni-style `position_id_per_seconds` mapping for audio tokens in M-RoPE.
5. **4B LoRA** (tiny) if projector-only underfits.
6. **Proper HF `Processor` class** + vLLM serving of the grafted model (needed before the downstream agentic stage runs at scale).
7. **Manufactured freq/stereo corpus** at scale; external datasets if diversity is wanted (research picks: FMA full `benjamin-paine/free-music-archive-full` on HF for 44.1k stereo music pool with per-track license flags; `cvssp/WavCaps` 403k captioned clips academic-only; Clotho v2 Zenodo 4783391 for eval; MUSDB18 for stereo eval — all NC except FMA).
8. Downstream: the actual agentic/synth reproduction training on top of the grafted 4B.
